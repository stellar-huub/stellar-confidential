# Brand assets

Logos, banners and social imagery for Confidential Stellar Infrastructure.

Everything here is generated by [`generate.py`](generate.py) — the marks are geometric, so they are computed from one set of polar helpers rather than hand-drawn. Edit the script, not the SVGs.

```bash
./generate.py          # rewrite every SVG
./generate.py --png    # also rasterise, via headless Chrome
```

## The mark

A hexagonal seal ring around a six-blade aperture.

An aperture rather than a padlock, deliberately. The project is not about hiding everything from everyone — it is about **controlled disclosure**, and an iris is the shape that says "opens by exactly as much as it is told to". A padlock would say the opposite, and would misrepresent what the auditing and viewing-key work is for.

Each blade spans 60° minus a small gap, with its inner edge rotated 26° against its outer edge. That twist is what makes six flat polygons read as overlapping blades. Alternating opacity gives depth without a second colour, so the mark still works stamped in a single ink.

The favicon is not a scaled-down logo: at 32px the detail closes into a blob, so it gets a heavier ring of its own.

**This is the project's own mark.** It is not Stellar's, is not derived from Stellar's, and should not be presented as an official Stellar asset. Stellar's name and marks belong to the Stellar Development Foundation.

## The background motif

The faint rows behind the wordmark on the banner and social card are a ledger: variable-width public columns beside one uniform, accent-coloured amount column.

That is the problem statement in a single glyph. Everything about a payment stays legible except the amount — and because the sealed cells carry the accent, what is protected is also what the eye lands on.

## Two constraints worth knowing before you edit

**No CSS inside the SVGs.** GitHub sanitises SVG rendered in Markdown and `<style>` blocks do not survive it. Everything is a presentation attribute. If you add a `<style>` block it will look correct locally and break on GitHub.

**No `prefers-color-scheme` inside the SVGs.** It is unreliable for images. Light and dark are separate files, chosen by `<picture>` in the consuming page:

```html
<picture>
  <source media="(prefers-color-scheme: dark)" srcset="assets/banner-dark.svg" />
  <img alt="Confidential Stellar Infrastructure" src="assets/banner-light.svg" />
</picture>
```

**Fonts are referenced, not embedded.** The wordmark renders with whatever the viewer's system resolves from the stack. That is fine for a README and acceptable for the docs site. If you need a fixed rendering — print, a partner deck, anywhere the exact letterforms matter — convert the text to outlines first.
